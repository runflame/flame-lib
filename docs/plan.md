# Flame implementation plan

- 🎻 Cell Type Language: first prototype implemented; see the [CTL specification and examples](../cells/ctl.md). Byte-oriented `.ctl` schemas use Rust-like syntax, earlier-field array lengths, `U8`/`U16`/`U32`/`U64` little-endian integers, canonical unsigned LEB128 as `V128`, and `^` Cell references. The compiler generates Rust Cell codecs; TL-B linear inversion (`~`) is excluded.
- Root-last graph transport implemented: see [the format and APIs](cells.md#root-last-graph-transport). One rooted DAG in children-first order, deduplicated Cells, backward `V128` reference indexes, and the final Cell as root. Hash preimages remain independent; availability and typed snapshots are ordinary Cell hierarchies with explicit pruning. The flat bag commitment and root-ID prefix are removed.
- Transaction CTL layout implemented: [flamevm/tx.ctl](../flamevm/tx.ctl). Tx has one body reference, inline 64-byte signature (zero means absent), and U16-length R1CS proof. TxBody has the header, program graph container (executable Cell and lookup snapshot), and a canonical mask-one pruned TxLog; VM checks the computed hash(0) and depth(0). Body ID is TxID, Tx root ID is WitnessID; both prover and verifier bind the original program graph, even after `exec`.
- Implemented `pushcell` (0xa6) and `exec` (0xa7). All frames execute raw Cell payloads with independent consuming byte/ref cursors, no program length prefix or Snake decoder. `exec` replaces the current code Cell, resets local cursors/labels, and preserves frame identity, stack, gas and rollback escrow. The builder packs straight-line code into instruction-aligned `pushcell exec` continuations; oversized instructions and automatic splitting of labeled programs are rejected.
- Make `input` use the raw Cell on the stack as the encoding of a Contract, supplied by `pushcell`; the current String32 hash selector remains temporarily.
- Finish the direct Cell-based Taproot-opening API: `open` already resolves/executes authenticated native program Cells, but its stack selector remains internal key + String32 root + index. Replace that selector with the intended `pushcell` interface and integrate explicit level-zero virtualization. A pruned Cell may supply a commitment but attempts to execute/read its body must fail. Keep `open` as an isolated child frame, unlike same-frame `exec`.
- Review graph-aware script-size admission policy. The retained `script()` byte view and script-byte limits now cover root bytecode only; transport-byte and gas limits still bound the whole supplied/executed graph. No automatic legacy-state migration is provided for changed code, predicate and transaction IDs.
- VM Builder/Slice byte operations implemented: reads/writes/appends, in-place bit operations/shifts, Cell/Slice/Builder/Dict `size`, factual Cell/Slice/Builder `eq`, and raw SHA digests appended into an explicit Builder. `cellhash` exposes a chosen Cell hash level for semantic comparison. Native literals use `pushcell`; Cells/Slices use existing `dup`. Decide the remaining String/transcript/typed conversion operations before removing temporary String Values and byte-only host-source compatibility. Pruning/virtualization VM operations remain unimplemented.
- think on how to bring pruned txid cell into the tx so it commits to the results explicitly so we can query them in merkleized manner without having to run the VM. Alternatively, the block inclusion may have those results, but those do not depend on the position in the block and fully determined by the transaction's author, so should be precomputed and embedded as a pruned cell.
